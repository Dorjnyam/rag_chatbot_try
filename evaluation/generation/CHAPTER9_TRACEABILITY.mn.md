# Phase 6 — Chapter 9 Research-to-Code Traceability

## Хамрах хүрээ ба үнэлгээний дүрэм

Chapter 9-ийн 9.1–9.11 хэсгийг `app/services/rag.py`, `app/services/openai_provider.py`, `app/services/language.py` болон одоогийн test suite-тэй тулгав. Chapter 8/10-ийн supporting mapping ба бодит offline хэмжилтийг `RESULTS.mn.md`-д хадгална. Судалгааны жишээ, зөвлөсөн архитектурыг төслийн хэмжилт гэж тооцоогүй.

Status нь тодорхой capability болон түүнийг батлах тестэд хамаарна:

- **IMPLEMENTED_VERIFIED** — код болон deterministic тестээр тухайн хязгаарлагдсан үйлдэл батлагдсан.
- **PARTIALLY_IMPLEMENTED** — зарим хамгаалалт байна; шаардлагатай invariant эсвэл coverage дутуу.
- **IMPLEMENTED_UNVERIFIED** — код байгаа боловч шаардлагатай behavior test-ээр батлагдаагүй.
- **NOT_IMPLEMENTED** — одоогоор capability байхгүй.
- **DEFERRED** — хэмжилт/annotation өгөх үндэслэл хүртэл хойшлуулсан.
- **NOT_APPLICABLE** — энэ төслийн одоогийн flow-д хамаарахгүй.

## Нэмэлт critical findings

1. Өмнөх `validate_answer` хувилбар `insufficient_evidence` хариултад inline citation ба `sources` зөрөх, duplicate sources, JSON нэмэлт талбар зөвшөөрдөг байв. Одоогийн хувилбарт эдгээрийг fail closed болгосон.
2. Өмнөх production flow citation-ийг retrieval pool-ийн mutable `label`-ээс сэргээдэг байв. Одоогийн `build_context(..., include_references=True)` сонгогдсон evidence-ийн canonical reference map буцааж, citation resolution-д зөвхөн түүнийг ашиглана.
3. Repair хүсэлт өмнө нь configured input budget-аар шалгагддаггүй байсан. Одоо serialized repair request хэтэрвэл model дуудалгүй deterministic fallback хийнэ.
4. Generation config snapshot өмнө нь provider-т илгээдэггүй `temperature=0` гэж тэмдэглэдэг байсан. Одоо `temperature: null`, бодит reasoning effort, schema revision-ийг бүртгэнэ.

Эдгээр deterministic шалгалт нь citation/source identifier-ийн consistency-г батална; human-reviewed claim support буюу бодлогын зөв хариултыг батлахгүй.
